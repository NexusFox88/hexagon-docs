## Registry 与网络限制

[镜像引用解析](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/modules/harnesses/registry.ts)接受 Docker Hub（`docker.io`，省略时默认）和 GHCR（`ghcr.io`），不接受任意 registry URL。固定解析器对其他来源或不合法引用返回 `invalid_image_reference`（400）。认证 token 响应限制为 65536 字节，所读取的 manifest／配置响应限制为 4 MiB；超限产生 `image_manifest_too_large`（400）。这些是元数据读取边界，不是全部镜像层或安装后文件系统的 4 MiB 上限。blob 重定向也有明确目标策略，添加凭据不会绕过检查。Provider 是否支持私有镜像仍需单独判断。

[Session 网络 schema](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/modules/execution/sessions.ts)允许 `unrestricted` 或 `allowlist`，默认 unrestricted、空主机列表。主机条目为非空字符串；这个 schema 没有定义统一的条目数量或单主机长度最大值，不能由此推断 Provider 支持无限配置。[组合解析器](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/modules/execution/compatibility.ts)用 `network_policy_unsupported` 或 `credential_proxy_not_allowed_by_network_policy` 拒绝不支持的 allowlist 或缺少凭据入口访问权限；创建时将兼容性原因作为 400 返回。应保留所需策略并选择支持的 Provider。这些检查不证明实云防火墙执行效果。

## Tool、Provider 与账户限制

[Remote MCP](/zh-CN/integrations/mcp)当前限制发现最多 100 个工具、最多 20 页和单个响应 2 MiB，具体检查见 [remote.ts](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/integrations/mcp/remote.ts)。具名应用响应体限制为 1 MiB，见[应用请求实现](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/integrations/apps/registry.ts)。这些是协议传输限制，不是 workspace 文件大小。

Provider 的内存、CPU、创建并发、存储、镜像权限及 API 配额取决于连接配置和实际账户。按 [Sandbox 集成](/zh-CN/integrations/sandboxes)查对应 Provider；不能把试用账户的并发限制写成 Hexagon 全局配额。私有 OCI、网络 allowlist、暂停恢复必须由当前连接器声明支持，不支持的策略不能静默降级。

一些连接器有更小的文件或命令限制。传输队列上限约束缓冲区，不一定限制整个响应总长。不要把它与上传请求、导出产物或 Provider 磁盘容量互换。容量和成本规划见[容量指南](/zh-CN/operate/capacity-and-cost)。

## 按接口实际检查的方式计算大小

文本需要同时计算 JavaScript UTF-16 code units 与 UTF-8 字节。包含 41000 个 `中` 的任务有 41000 个 code units，却有 123000 个 UTF-8 字节：字段长度合格，仍超过输入与背景合计 120000 字节的上限。一个 `😀` 占两个 code units、四个 UTF-8 字节。Python 的 `len(text)` 统计 Unicode 码点，不能直接代替 schema 的 JavaScript 长度。

上传 `n` 个二进制字节时，标准 Base64 长度为 `4 × ceil(n / 3)`。1572864 字节的文件编码后为 2097152 字符，符合字段上限；再增加一个字节，编码长度就变成 2097156，超过上限。JSON 中的路径、键名、引号和分隔符还会增加 HTTP 请求体大小。需要同时检查最终序列化请求与解码字节。六个各为 1.5 MiB 的文件可以通过分批解决单请求 8 MiB 总量限制，但分批不能让超限的单文件合法。

所有上传批次必须在**首个 Run 或 Sandbox 分配之前**完成。之后上传会产生 `workspace_already_started`；按[项目上下文](/zh-CN/build/project-context)准备初始输入，后续由 Agent 工作修改活动工作区。同一请求内重复路径产生 `duplicate_input_path`；执行开始前，后一次请求可以替换此前上传的同一路径。核对返回的大小与 SHA-256，不要假定每次上传都会追加一个新文件。

环境变量限制统计 `JSON.stringify(env)` 的字节，包括键名和转义。初始化限制也包含序列化结构及编译后的背景包装文字，因此多个单独合法的文档仍可能合计超限。每个字段的最大值不代表所有字段都能同时填满。

## 定位拒绝发生在哪一层

| 失败阶段 | 可观察结果 | 对应处理 |
| --- | --- | --- |
| HTTP 请求体解析 | 请求体超限返回 HTTP 413、`invalid_http_request` | 缩小完整序列化请求；Base64 字段合法不能证明请求体合法 |
| 公共请求 schema | HTTP 400、`invalid_request`，附带违规 `fields` 路径 | 修正数量、类型、长度或路径；内部 schema 消息不一定作为公共错误码返回 |
| 上传解码总量 | HTTP 413、`upload_too_large` | 在执行开始前分批上传单独合法的文件 |
| 编译初始化／Run 输入 | HTTP 413、`initialization_too_large`／`input_too_large` | 缩小编译背景或任务文本，检查字节而不只看字符数 |
| 产物捕获 | 捕获路径中的 `invalid_artifact_manifest` 或 `artifact_integrity_failed` | 检查实际导出列表、大小、重名、编码和哈希；捕获属于 worker 活动，不是客户端上传端点 |

产物捕获在数据库事务之前检查 manifest。被拒绝的 manifest 不会成为部分接受的列表，也不会删除此前已提交的产物。Run 到达终态不能证明所有预期文件都已导出；需要查询已记录的产物列表并验证所需字节。

## 超限后如何处理

schema 拒绝与领域错误分别检查；例如输入和背景合计超限返回 `input_too_large`（413），初始化超限为 `initialization_too_large`（413）。产物总量或重复名称可触发 `invalid_artifact_manifest`，单文件大小、编码或哈希不符可触发 `artifact_integrity_failed`。这些错误不应通过重复同一请求解决。

缩小输入、分批上传、只导出必要文件，或选择能力合适的组合。不能通过分批上传绕过单文件边界，也不能把用户要求的 allowlist 改成 unrestricted 来“通过”。网络错误或 Provider 配额拒绝与 Hexagon 输入超限分开处理；创建请求结果未知时先对账原操作，不能换 key 反复创建。

本页数值经过源码核对；局部编码和 schema 求值结果见[限制参考核对记录](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/testing/evidence/2026-11-20-limits-reference-review.json)。这些检查不代表完整边界覆盖或实云压力测试。没有明确列出的账户总容量、整体吞吐量或价格不代表无限，也不构成服务级别承诺。
