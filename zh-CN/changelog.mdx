## 辨识准备采用的开发快照

将变更与实际安装的源码或发行产物对应。两种 SDK 的版本可能在多次源码变更后仍为 `0.1.0`，仅凭这个数字不能判断已包含哪些变化。本地发行目录的 `release.json` 由[本地构建器](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/tooling/build-local.ts)生成，包含 `format`、`sha256` 和 `built_at`。其中指纹标识构建内容，不是签名发布、Git revision 或兼容性保证。另行记录源码 revision 与本地修改，并保留匹配的 lockfile 和 SDK 产物。

例如，下文直接创建 Session 的变化对应[迁移 016](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/modules/storage/016-direct-sessions.sql)：移除 `sessions.agent_id` 与 `sessions.agent_revision` 的 `NOT NULL` 约束。在旧控制平面前安装新版 SDK 不会替部署执行数据库迁移。按升级流程对齐部署后，再通过 API 验证行为。

## 2026-11-19：E2B 公有 OCI 镜像准备

**影响。** E2B 可将公有 OCI Harness 镜像准备成 Session 专属模板，在创建计算资源前独立记录模板和构建操作。新增了构建阶段与清理责任，不包含私有镜像仓库或跨 Session 模板缓存。内置 Harness Session 继续使用配置的模板。

**操作。** 阅读 [E2B 前置条件](/zh-CN/integrations/sandboxes/e2b)和 [OCI 注册](/zh-CN/integrations/harnesses/oci)，选择兼容的不可变 Harness 定义并创建新 Session。等待准备结束，不能因响应丢失就发起另一个构建。计算资源与所属模板都确认清理前，保留模板和构建操作引用。本次增量没有改变 SDK 的 Session 输入形态。

**验证。** 检查初始化、准备状态、实际执行与清理。[日期证据](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/testing/evidence/2026-11-19-e2b-oci-preparation.md)覆盖特定 OpenCode digest、安装后 Python 的 Chat Completions 与 TypeScript 的 Anthropic Messages、暂停前后实际文件哈希和原生状态、MCP、产物与清理。它不证明全部 SDK/协议交叉组合、Responses 或所有 E2B Harness。早期失败仍保留为失败；本次增量的清理审计不包含另行搁置的历史操作。

## 2026-11-19：Harness 暂停唤醒与 Playground 展示

**影响。** Serverless 验证按 Harness 和 Provider 区分实际文件与对话恢复。Console 将 SDK、REST API 作为同级表示，并修正暗色应用图标。切换代码表示保留草稿，不会提交任务。

**操作。** 阅读[无服务器生命周期](/zh-CN/concepts/serverless-lifecycle)与[空闲唤醒](/zh-CN/build/idle-and-wake)，核对具体组合再判断内存或文件系统恢复能力。改变固定 Harness 定义时创建新 Session。不能把 Provider 自动休眠当作确认删除，也不能把文件系统恢复当作全部进程仍在运行。

**验证。** 追问需要保持目标文件字节和对话状态，并完成确认清理。[日期记录](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/testing/evidence/2026-11-19-harness-serverless-ui.md)保留实际失败、修复与 UI 检查；[已验证组合](/zh-CN/integrations/verified-combinations)说明矩阵范围。较早矩阵的 OCI 排除项属于当时快照，前述 E2B 增量在之后补充限定范围证据，不能把旧行改写成已经测过新实现。

## 2026-11-18：读取历史 Session 初始化

**影响。** Console 和两种 SDK 可读取有效初始化快照，包括固定定义、适用时的源 Agent revision、环境变量名称与明确的脱敏元数据。它描述历史初始化，不是当前 Runtime 健康状态，也不是包含凭据的重放配置。

**操作。** SDK 缺少 Python `session_initialization` 或 TypeScript `sessionInitialization` 时更新安装产物。用快照调查 Session 实际收到的配置，不从中还原凭据，也不预期连接重命名会改变历史初始化。

**验证。** 两种客户端读取同一 Session 并比较快照，确认跨租户访问被拒绝且没有秘密值。[证据](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/testing/evidence/2026-11-18-session-initialization.md)包含安装包测试、对既有云 Session 的只读查询和双语浏览器检查；该查询不是新云执行。参见[初始化说明](/zh-CN/concepts/initialization)。

## 2026-11-18：Remote MCP、飞书/Lark 与 Responses

**影响。** Remote MCP 将发现并选定的 Tool schema 接入共享 broker；飞书/Lark 增加应用凭据交换与固定操作；OpenAI Responses 是独立模型协议，不能由 Chat Completions 连接成功推导支持。

**操作。** 按 [MCP](/zh-CN/integrations/mcp)、[应用账户](/zh-CN/integrations/apps)、[模型协议](/zh-CN/integrations/model-protocols)配置。MCP 定义变化后重新验证再使用；显式选择 Responses 和兼容 Harness。已有不可变 OCI 注册保持原定义，兼容性元数据扩展不会修改它们，必要时注册新版本并创建新 Session。

**验证。** 检查选定操作、授权审批和实际模型协议。[原增量证据](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/testing/evidence/2026-11-18-mcp-lark-responses.md)把 DeepWiki MCP 真实云旅程，与飞书/Lark 确定性覆盖、真实 CLI 配合 fixture Responses 服务的检查分开。后续矩阵可能扩展特定组合，但仅凭原记录不能证明真实 Lark 账户或真实 Responses 模型已通过。该变化也不提供任意 MCP 服务的自动 OAuth 接入。

## 2026-11-17：直接创建 Session，保存 Agent 可选

**影响。** 应用可以直接以 Harness、Sandbox 和模型连接 ID、可选 Tools 与环境创建 Session，不必先保存 AgentDefinition。Console 入口围绕 Sessions、运行连接和 Tool 连接组织；已有保存 Agent 的请求继续支持。

**迁移操作。** 先创建匹配的离线备份并处理已有资源，再按[升级步骤](/zh-CN/operate/upgrades)应用目标源码。迁移 016 允许 Agent 引用为空，保留已有数据。应用读取逻辑需要接受直接 Session 的 `agent_id`、Agent revision 为空。去除业务层“启动前必须保存 Agent”的强制步骤；需要复用定义时仍保留 Agent 路径，不改写旧 Session 定义。

**验证示例。** 两种 SDK 分别在不创建 Agent 的情况下直接创建 Session，执行真实任务，检查最终结果与可空 Agent 引用，然后关闭并确认 Provider 删除；可选 Tool 绑定单独验证。[日期检查点](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/testing/evidence/2026-11-17-minimal-session-console.md)记录 Vercel/Pi 与已有 SiliconFlow 连接上的独立旅程，其中一项使用 Exa，还包括安装包、API 和浏览器检查。它复用了凭据，没有重跑全部 Provider、授权或完整 Web 场景。这是源码变更迁移示例，不是虚构的正式版本发布。
