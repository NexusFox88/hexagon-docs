## 如何解读一条记录

1. **固定身份**：确认 builtin Harness 的 version，OCI 的完整 digest、protocol 与 command；内置 OpenCode 和 OCI OpenCode 是不同路线。
2. **模型范围**：核对实际 endpoint、model ID 与 Messages / Chat Completions / Responses；同一厂商不意味着协议等价。
3. **客户端**：检查 Python 和 TypeScript 独立结果、安装版本与场景。不能由 Python Harness 推断 Python SDK 通过。
4. **具体分支**：任务、上传、Tools、审批、事件重放、产物、继续对话和恢复各自查看。Aider 等有限契约不能被标为具有未执行的 Tools/产物能力。
5. **清理**：区分该成功尝试的 Session 清理、同组合早期失败尝试的未决资源，以及账户全局资源审计。

任务矩阵保留 attempts。一个最终 passed 行仍可能包含早期失败或未确认创建。不要丢弃失败历史或据通过行声称全局没有孤儿资源。原始资源 ID 留在私有证据中供对账，公共页面只链接脱敏摘要。

## 状态与证据类型

| 类别 | 含义与动作 |
| --- | --- |
| 已通过 | 只对记录中的版本、账户条件、SDK 和场景成立 |
| 支持但未验证 | 有实现或声明，缺少目标范围实测，需安排验证 |
| 失败 | 某次执行未满足断言，保留原因与清理状态 |
| 阻塞 / unknown | 凭据、额度、网络或远程结果无法确定，不计入通过 |
| 有条件通过 | 明确满足前提的部分范围成功，必须保留条件，不归并为无限制通过 |
| 不支持 | 当时契约不提供该组合，不等于测试失败；新实现可能需要新记录 |

契约/模拟测试证明确定性逻辑，真实云任务证明当次远端行为。源码注册表声明的 implemented 或 live_resource 标签不能代替具体端到端记录。页面结构检查也不证明示例或云行为。

## 时间变化的具体例子

旧 MiniMax 矩阵中 E2B OCI 行不支持，是当时能力快照。随后 E2B 新增 Session 自有 Template 准备，专项记录给出了 OpenCode 镜像的 Python/Chat 与 TypeScript/Messages 旅程、文件字节 hash 和 native session ID 检查。它没有证明 Responses 或所有 SDK/协议交叉组合。

专项保留了模型输出不精确导致的失败，以及后来澄清提示后的成功；不能回写早期失败为通过。其独立资源审计只覆盖该次增量，不包括另行保留的历史操作。相同原则适用于其他 Provider 的新版本和恢复改动。

## 重新计算快照计数

从仓库根目录运行。这里只读取本地脱敏证据，不请求 Provider 或模型；输出重现上方状态计数，不重新执行验收，也不将两个矩阵合并成同一个统计单位。

```sh
python3 - <<'PYCOUNTS'
import json
from collections import Counter
from pathlib import Path
for name in ('2026-11-18-minimax-matrix.json',
             '2026-11-19-harness-serverless-matrix.json'):
    data = json.loads((Path('testing/evidence') / name).read_text())
    print(name, data['checked_at'])
    print(dict(Counter(row['status'] for row in data['rows'])))
PYCOUNTS
```
