Repository instructions still govern edits, tests, credentials and publication in your checkout. This Markdown file is the reading entry point; it does not imply an available hosted documentation endpoint or a separate machine API.

## Select the contract before constructing a call

Use the exact resource reference for parameters, authorization, response shape and side effects. The guides explain how to assemble those calls into an application; they are not a substitute for the contract.

| Intended action | Contract to read | Decision to preserve |
| --- | --- | --- |
| Configure/validate execution prerequisites | [Connections](/en/reference/connections), [Harness registration](/en/reference/harness-registration) | Connection readiness, selected version and actual capability support |
| Preflight, create, upload or close | [Sessions](/en/reference/sessions) | Creation intent, pinned definition and cleanup outcome |
| Submit, query or cancel a task | [Runs](/en/reference/runs) | Same input/origin/key for retries; cancellation is explicit |
| Observe progress | [Events and states](/en/reference/events-and-states) | Public event cursor differs from Runtime cursor; unknown events cannot invent state transitions |
| Decide a Tool action | [Approvals and Tool calls](/en/reference/approvals-tools) | Account authorization, operation approval and outcome reconciliation remain distinct |
| Deliver files or previews | [Artifacts and previews](/en/reference/artifacts-previews) | Artifact integrity and preview authorization have separate lifecycles |
| Investigate resource uncertainty | [Resource operations](/en/reference/resource-operations) | Original operation/resource identity and review state; acknowledgement is not completion |
| Translate calls to SDK code | [Python](/en/reference/python), [TypeScript](/en/reference/typescript), [errors](/en/reference/errors) | Actual method signatures, error handling and language-specific byte/cursor types |

Begin at the [HTTP reference index](/en/reference/http) when you cannot identify the resource. These are version-sensitive repository references; verify them against the checked-out source when changing contracts. Do not derive an endpoint by guessing from an SDK method name.

## Journal facts must survive a process restart

Treat the following as application data requirements, not a new Hexagon JSON schema:

- The original submission contains Session ID, exact input, exact origin and the stable idempotency key. Keep it before the network call so a lost response can be recovered.
- Run ID and a decimal-string event cursor identify accepted work and observation progress. Save each event and its advanced cursor atomically; an in-memory map does not survive a worker restart.
- Keep creation/closure intent separate from confirmed results. An operation ID, remote resource ID and unresolved outcome are evidence to reconcile, not instructions to repeat the mutation.
- Keep authorization material out of the ordinary journal. If a preview URL must be retained, use private storage with appropriate access controls; that URL can itself grant access.

For example, a journal holding Run R and committed event cursor `104` after a client crash means “observe R after 104,” not “resubmit the task.” A journal holding only a Session-creation intent means “investigate whether creation succeeded,” not “allocate another Session.” Different missing fields imply different recovery actions.

Repository development rules remain in [AGENTS.md](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/AGENTS.md); this integration guide does not replace them. Continue with [combination selection](/en/integrations/choose), the [HTTP index](/en/reference/http) or [reconciliation](/en/operate/reconciliation).

## Integration algorithm with a durable journal

The following is pseudocode. `journal`, business authorization and transactions are application-owned, not Hexagon SDK methods. The concrete Python and TypeScript calls are in the linked build guides and [first-Session examples](https://github.com/NexusFox88/hexagon-docs/blob/main/resources/examples/documentation/first-session.py).

```text
authorize business user against the work context
load/create a private journal for this business request
record selected connections, exact Harness version, policy and creation intent

if Session ID is absent:
    if a previous create request has an unknown outcome:
        investigate Sessions and resource operations; stop automatic creation
    create Session once; persist returned Session ID

commit submission intent:
    Session ID, exact input, exact origin, one stable idempotency key
submit that saved intent; persist returned Run ID
if submission response is lost:
    retry the same Session/input/origin/key with bounded transport backoff
    never generate a new key to conceal a conflict

cursor = last committed event ID, or string "0"
observe original Run after cursor
for each event with an ID:
    transactionally deduplicate/store event and advance cursor
for stream loss:
    reconnect to the same Run with the committed cursor
for authorization/approval wait:
    surface the original request to the permitted decision-maker
for unknown Tool result:
    record call ID, request hash and dispatch policy
    investigate externally; do not re-dispatch the write

query the Run for its terminal state and final output
verify/download authorized artifacts; preserve intended follow-up context
when the Session is no longer needed:
    record close intent; request closure; verify confirmed cleanup
    retain pending operation/resource IDs until reconciliation finishes
```

Record at least business request/owner, Session ID, Run ID, exact submission payload/key, event cursor, cleanup intent/status and unresolved operation references. Resource identifiers belong in private evidence, not public example output. Store timestamps and errors without logging Tokens or original account credentials. Every external lookup and result delivery still requires application authorization, even when several business users share one Hexagon tenant.

Run submission idempotency does not extend to Session creation or arbitrary provider operations. Event IDs should remain numeric strings, not JavaScript Numbers. An event without a durable ID, such as `stream.end`, is not a cursor checkpoint. A drained stream or empty event page does not replace the terminal Run query. A network disconnect does not cancel execution.

## Conditions that change the next action

| Condition | Action |
| --- | --- |
| Unsupported model protocol/network/Tool capability | Correct selection before allocation; do not silently weaken the requested policy |
| `session_busy` | Keep the application message pending until the active Run settles, or use a deliberately separate Session |
| Idempotency conflict | Compare stored input/origin/key; do not manufacture a new request to hide the conflict |
| Authentication/permission error | Correct identity or authorization; do not loop transient retries |
| Missing Tool authorization | Obtain authorized account access through the existing flow; do not pass upstream keys to the guest |
| Pending write approval | Wait for a permitted decision; a model instruction is not approval |
| Unknown create/write/delete outcome | Reconcile the original operation; absence of a response is not proof of failure |
| Failed or cancelled Run | Inspect output, events and possible side effects before another task; cancellation does not undo writes |
| Unconfirmed cleanup | Retain the journal and provider identifiers; do not mark the account free of orphan resources |

## Use examples and evidence accurately

Examples have different scopes: a complete tutorial, an SDK excerpt requiring existing variables, a structural sketch, or a deterministic fixture. Read the label and prerequisites before executing. Placeholder connection IDs, `.invalid` domains and local image tags are not deployed services. A fixture model does not prove real model behavior; a registered Harness does not prove that image/provider/protocol combination works.

For each integration change, report the files changed, actual commands and outcomes, exact tested scope, limitations and cleanup status. Preserve failed attempts. Follow [testing and evidence](/en/contribute/testing) and both SDK journeys where the change affects their shared contract. Do not use generated Agent text as proof that tests passed: inspect actual test output and artifacts.
