# Instabox P0 recovery acceptance — 2026-11-16

## Implemented behavior

- A structured synchronous create `429 quota_exceeded` without an operation ID is persisted as `rejected`, and the Run terminates with `sandbox_quota_exceeded`. A reconstructed lifecycle does not retry it. Closing that Session succeeds without looking for a nonexistent resource. Capacity must be released and a new Session/Run created explicitly.
- Generic HTTP 429, `rate_limited`, errors carrying operation IDs, and quota errors during operation polling remain uncertain. No raw provider error body is persisted or shown. Error parsing is bounded to 16 KiB.
- Connection validation and worker provisioning check local `ssh` (OpenSSH) and actual ed25519 generation with `ssh-keygen` before provisioning intent/provider effects. Missing dependencies yield `sandbox_openssh_unavailable`, and a failed Run does not leave an unknown resource operation.
- Both errors and the rejected resource-operation state have English and Simplified Chinese Console messages. Invalid connection guidance survives refresh. All controls remain application-owned.

## Additional defect found and fixed: local SSH keys after SIGKILL

The first full worker-crash journey left one legacy-format temporary SSH key/certificate directory because SIGKILL skips finally handlers. No SSH process or cloud machine remained. The directory was positively associated with this turn's crash timestamp and was removed explicitly; generic cleanup deliberately does not remove unmarked legacy directories.

New directories include their owner PID. Preflight and tunnel creation sweep same-user, real directories whose owner PID returns ESRCH. They preserve active processes, different owners, symlinks, unmarked directories and ambiguous process errors. PID reuse conservatively preserves the directory. The sweep is throttled within a process and runs on first use in a fresh process; this is restart/next-use cleanup, not a claim that code executes after SIGKILL or while the host is offline.

`npx tsx tooling/check-instabox-ssh-crash.ts` passed against a real Instabox machine. Journal: `.local/evidence/instabox-ssh-crash-1de6ee9b-ad6f-42bb-bad1-3868e6db08d9.json`. A child obtained an actual SSH certificate and completed a private HTTP request. A fresh-process preflight preserved its directory while the child was alive; after SIGKILL another fresh-process preflight removed it. Cloud resource cleanup was confirmed. The final full regression result is 50 files / 144 tests. The local service was restarted again to load this final fix.
