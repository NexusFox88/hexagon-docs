## Registered Connector and Runtime readiness

The shared registry and Console now support Agent37. The adapter creates base instances with 2 vCPU / 4 GiB / 4 GiB disk, no public ports, auto-sleep disabled and managed-model cap zero. It declares shared control-plane expiry. Only 404 is absence; stopped/sleeping resources are not automatically executed. Files are chunked below API limits and renamed atomically on write; truncated command responses and incomplete reads fail explicitly. Reads are limited to 64 MiB. Network allowlists, pause/resume and snapshots are not advertised.

Two initial managed-expiry attempts failed the Runtime authentication assertion and were cleaned: `agent37-3cd3db2e-9d4e-4f35-a596-f09b8fa838f6.json` and `agent37-6671e808-0bbc-4054-beb0-52034396ddb7.json`. Investigation showed the provider edge reserves `/health` and returns its own unauthenticated `{ok:true}`. RuntimeClient now uses `/_hexagon/health` and requires state ready / protocol 1; Runtime preserves the old route for compatibility. The test supplies provider transport headers while omitting the Runtime bearer, independently checking the two boundaries.
